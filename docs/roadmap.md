# Roadmap

Pasos en orden. Cada uno termina con una verificación concreta contra datos
reales. El flujo actual sigue vivo hasta el corte, que es la última entrega del paso 4. Estado por feature en
`features.md`; estado por paso en la última columna.

No hay fase de copiar y podar: el store es propio y se escribe contra
`specs/data-model.md` (ADR 0011). El DDL es el primer artefacto y el único
acoplamiento entre el store y el importador, así que desde el paso 1 los dos
avanzan en paralelo contra el mismo schema.

## Deuda conocida al arrancar

- El gate `require-progress-report` necesita que el input de `SubagentStop` identifique el transcript del subagente. La documentación oficial lo confirma (`agent_transcript_path`, `specs/hooks.md#hallazgos-del-spike-de-claude-code`); falta ver el campo en un evento real, y eso lo hace el ensayo aislado del paso 3, antes de escribir el gate en el paso 4.
- El import corre con el daemon de Engram apagado. Si se corre con el daemon vivo, el ATTACH de solo lectura sobre WAL puede ver una base a mitad de un checkpoint; `--dry-run` no lo detecta.
- `**Product**` es prosa: el import la consolida solo en 4 productos (`tripulse` y los personales `ai-review`, `dev-loop`, `engram-fork`) y deja el original en `notes` como procedencia, y arma `parent_task_id` desde los indicios y la regla de socios de negocio (`specs/import-legacy.md`, decisión del 2026-10-20). Queda para el CLI el ajuste fino que esa regla no cubra.
- El dedupe por hash y ventana es la rama más intrincada de `AddObservation` y se disparó dos veces en toda la historia de la base: 2 observaciones con `duplicate_count > 1`. El upsert por `topic_key`, en cambio, es carga real: 757 con `revision_count > 1`. Escribir las dos con el mismo cuidado es desperdiciar el cuidado.
- La absorción deja vencida la sección `## Engram — persistent memory` del `~/.claude/CLAUDE.md` global del usuario (fuera de este repo): habla de guardar el `id` de observación/prompt como clave (ahora es `sync_id`, ver `specs/api.md#convenciones`), de registros de control por `topic_key` en el project `tasks` (ahora son `tasks`/`worktrees`/`progress_reports`), de leer por HTTP en `127.0.0.1:7437` (el daemon de neugram sirve en `:7438`, con otro contrato), y apunta a `~/.claude/docs/engram-api.md`/`engram-setup.md` para las recetas (ese contenido pasa a vivir en `specs/api.md`/`specs/hooks.md` de este repo). El paso 3 de `specs/import-legacy.md#corte`, que ocurre con el corte del paso 4, ya reemplaza la sección entera por dos líneas a `neugram instructions show`; es el mismo trabajo que F8 (migrar instrucciones a la tabla `instructions`), no un pendiente aparte.
