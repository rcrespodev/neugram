reales. El flujo actual sigue vivo hasta el paso 3. Estado en `features.md`.

No hay fase de copiar y podar: el store es propio y se escribe contra
`specs/data-model.md` (ADR 0011). El DDL es el primer artefacto y el único
acoplamiento entre el store y el importador, así que desde el paso 1 los dos
avanzan en paralelo contra el mismo schema.

## Deuda conocida al arrancar

- Tres semánticas del store sólo existían en el código de Engram y hay que fijarlas antes de escribir el paso 1a, no durante. `normalized_hash` ya está fijada y verificada (`specs/engram-provenance.md`). Faltan dos: el corte de relevancia de `FindCandidates` (`rank >= -2.0` en bm25, una constante sin justificación documentada, a recalibrar contra las observaciones importadas) y la sanitización del query FTS —la de Engram no cumple el `match_mode: any` que pide `specs/api.md`, así que es diseño nuevo, no re-derivación.
- El gate `require-progress-report` necesita que el input de `SubagentStop` identifique el transcript del subagente (no el del padre). Verificarlo contra la versión de Claude Code que corre antes del paso 4; si no, el gate no se puede evaluar y F17 queda sin enforcement.
- El import corre con el daemon de Engram apagado. Si se corre con el daemon vivo, el ATTACH de solo lectura sobre WAL puede ver una base a mitad de un checkpoint; `--dry-run` no lo detecta.
- `**Product**` es prosa: el import normaliza 23 cadenas a 13 productos y deja el original en `notes`. La consolidación real la hace el usuario con el CLI después del paso 1b.
- El dedupe por hash y ventana es la rama más intrincada de `AddObservation` y se disparó dos veces en toda la historia de la base: 2 observaciones con `duplicate_count > 1`. El upsert por `topic_key`, en cambio, es carga real: 757 con `revision_count > 1`. Escribir las dos con el mismo cuidado es desperdiciar el cuidado.
- La absorción deja vencida la sección `## Engram — persistent memory` del `~/.claude/CLAUDE.md` global del usuario (fuera de este repo): habla de guardar el `id` de observación/prompt como clave (ahora es `sync_id`, ver `specs/api.md#convenciones`), de registros de control por `topic_key` en el project `tasks` (ahora son `tasks`/`worktrees`/`progress_reports`), de leer por HTTP en `127.0.0.1:7437` (el daemon de neugram sirve en `:7438`, con otro contrato), y apunta a `~/.claude/docs/engram-api.md`/`engram-setup.md` para las recetas (ese contenido pasa a vivir en `specs/api.md`/`specs/hooks.md` de este repo). El paso 3 de `specs/import-legacy.md#corte` ya reemplaza la sección entera por dos líneas a `neugram instructions show`; es el mismo trabajo que F8 (migrar instrucciones a la tabla `instructions`), no un pendiente aparte.
